Managed CLI and plugin launches now share a version-two transaction. Screen
admits a real placeholder before Git preparation. Strict worker insertion splits
a logical tiled region, including a complete controller stack/list, and later
workers join only that controller/tab's owned region. Floating and overlay
controllers retain their layer and focus. Pane limits include pending tiled
reservations. Failed geometric/capacity admission does not mutate live groups,
fullscreen, focus, or unrelated panes, and does not prepare Git or execute a
provider. Automatic overflow and intentional suppression retain separate policy.

The existing placement-before-exec barrier now carries typed decisions, launch
identity, allocation/placement generations, tab incarnation, controller identity,
and worker-region ownership. Screen revalidates after slow preparation. A shared
one-use permit orders revocation against exec. If start wins, cleanup owns the
late child and reader and waits for confirmed teardown off the event loops.
Ordinary Enter/rerun cannot start a held pending reservation. After handoff,
ordinary reruns are permitted, but their replacement process cannot inherit the
original launch receipt's availability.

The server runtime and host coordinator keep host/session-scoped persistent
receipts in plugin-data storage, using authored revision guards. Intent and the
starting boundary are recorded before side effects/execution. Environment values
are hashed, not saved. Matching IDs observe the same operation; conflicting
request digests do not change it. Registration and current placement are
acknowledged before successful handoff. Historical started receipts also report
current availability; closure or rerun never supplies a replacement worker.
Missing history and retired server incarnations never authorize replay.

Resource manifests distinguish owned terminal allocations/placeholders/processes
and created tabs from borrowed destination metadata. Git manifests record
borrowed, created, or incomplete retained-attempt provenance. Branches, worktrees,
and project directories are never deleted on failure. Empty created-tab cleanup
requires the original lifetime and exclusive activity; concurrent activity and
recycled IDs prevent destructive cleanup. Process certainty and cleanup_pending
are separate, including when teardown cannot be confirmed.

The CLI adds --launch-id, launch-support, and read-only launch-status, using the
distinct agent-launch-transaction-v2 request/capability. IPC still carries the
typed request as JSON; protobufs were not changed. Legacy spawn/plugin callers
adapt into the coordinator and retain their existing response shape.

The reusable Swamp behavior saves optional versioned launch identity before
spawn, observes that exact identity on launching resume, and keeps the original
readiness and once-only submission guards. Definitive terminal receipts permit
a deliberate lifecycle handoff even when Git paths remain. Pending, unknown,
mismatched, closed, or legacy ID-less launches do not trigger replacement spawn
or prompt replay. No actual saved task, approval, Agenda issue 16, historical
client-timezone lifecycle, or Swamp state was mutated. Timezone code is unchanged.
The parallel typed evidence-submission refactor was not implemented here; its

Material decisions and verification limits:
- Launch IDs are caller-chosen but server-incarnation-qualified. This is stricter
  than an arbitrary unqualified string and fences missing history after restart.
  Interactive callers generate it after support negotiation; lifecycle callers
  save it before sending a mutating request.
- The coordinator lives in the plugin host to share preparation without circular
  dependencies; the server supplies the shared runtime and durable data access.
- Existing SSH termination acknowledgement does not prove remote reaping. Such
  uncertain teardown stays unknown with cleanup pending. Docker SSH end-to-end
  tests were not run: the available fixtures belong to another worktree, which
  this assignment forbids disturbing. Local wrapper and OS tests were selected.
- Tests ran on Linux. Restart/history fencing uses deterministic journal/runtime
  tests; a real crash/restart and every platform/scheduling combination were not
  exhaustively exercised.
- Installed /home/zacharyhamm/.codex/skills/yinz-agents/SKILL.md remains unchanged.
