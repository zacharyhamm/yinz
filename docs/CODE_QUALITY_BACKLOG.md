# Code quality backlog

This checklist contains the unresolved findings from the systematic code-quality audit. The three
higher-ranked findings were fixed in the audit change set and are intentionally omitted here.

Scores use `(impact x urgency) / effort`, with each input rated from 1 to 5. Re-score an item when
new evidence changes its reach, frequency, or implementation cost. Unless an item says otherwise,
completion includes focused regression coverage and a passing `cargo x ci check`.

## Next up

- [ ] **#4 Fix plugin executor lock ordering and sparse-pool growth** — high, 8.0 (`I4/U4/E2`)
  - Evidence: `zellij-server/src/plugins/pinned_executor.rs:146,335` locks
    `thread_plugins` and `execution_threads` in opposite orders, while pool growth uses vector
    length instead of vacant slots.
  - Complete when all executor paths use one lock order, removed slots can be reused, and a
    concurrent register/unregister test cannot deadlock or strand work on thread 0.

- [ ] **#5 Keep release publishing from committing unrelated work** — high, 8.0 (`I4/U2/E1`)
  - Evidence: `xtask/src/pipelines.rs:419` runs `git commit -a` after only checking whether the
    worktree is dirty.
  - Complete when publishing rejects unrelated tracked/staged changes and stages only the files
    generated by the release workflow.

- [ ] **#6 Fail closed when a session-status probe errors** — high, 8.0 (`I4/U2/E1`)
  - Evidence: `src/commands.rs:534` converts `session_status` errors into an absent session before
    create/resurrection paths that can replace a socket.
  - Complete when probe errors retain their context, stop the operation, and a regression test
    proves the create/unlink path is not selected.

- [ ] **#7 Avoid no-op renders when clearing scrollback state** — high, 6.0 (`I3/U2/E1`)
  - Evidence: `zellij-server/src/route.rs:315`, `screen/thread_main.rs:1418`, and
    `panes/terminal_pane.rs:832` schedule a render even when the pane was not scrolled.
  - Complete when clearing scroll reports whether visible state changed and rendering occurs only
    for a real change, with a focused render-count or state-change test.

- [ ] **#8 Preserve every path in filesystem watcher events** — high, 6.0 (`I3/U2/E1`)
  - Evidence: `zellij-server/src/plugins/watch_filesystem.rs:41` collects all paths from one event
    into a single `PathBuf`, which concatenates multi-path rename events.
  - Complete when paths are flattened independently and tests cover multi-path create, update,
    delete, and rename notifications without sleeps.

- [ ] **#9 Make fallible plugin SDK queries return errors instead of panicking** — high, 6.0
  (`I3/U2/E1`)
  - Evidence: Result-returning functions around `zellij-tile/src/shim.rs:271` unwrap response reads
    and protobuf decoding; permission denial can legitimately produce no response.
  - Complete when transport, permission, and decode failures reach the caller through the existing
    `Result` APIs and focused plugin tests cover each failure class.

- [ ] **#10 Retain diagnostics from installed agent-report hooks** — high, 6.0 (`I3/U2/E1`)
  - Evidence: `src/hocus_hooks.rs:201` redirects stdout and stderr to `/dev/null` and always exits
    successfully, leaving stale agent state unexplained.
  - Complete when hooks remain non-disruptive but append failures to a bounded diagnostic file,
    and `hocus hooks status` identifies that file.

## High priority

- [ ] **#11 Bound or coalesce replaceable plugin work** — high, 5.3 (`I4/U4/E3`)
  - Evidence: the queues described in `docs/PLUGIN_RENDER_PIPELINE.md` retain every event/render and
    can put stale plugin work ahead of current input.
  - Complete when replaceable updates are coalesced without reordering non-replaceable events,
    cancellation still works, and saturation behavior is covered by tests.

- [ ] **#12 Use one fallible PTY child-wait path** — high, 5.3 (`I4/U4/E3`)
  - Evidence: `zellij-server/src/os_input_output_unix.rs:213` reaps with `waitpid` and then calls a
    helper whose `try_wait` panics on `ECHILD`; `login_tty` and spawn failures also panic.
  - Complete when exactly one component owns reaping, stop/continue notifications remain intact,
    spawn/setup failures return contextual errors, and the quit callback runs once.

- [ ] **#13 Validate downloader status and resume semantics** — high, 5.3 (`I4/U4/E3`)
  - Evidence: `zellij-utils/src/downloader.rs:73` does not reject HTTP errors or distinguish a
    honored Range response from a full `200` response before appending partial data.
  - Complete when only successful responses are cached, resume appends only a valid partial
    response, a full response replaces the partial file, and client-construction failure is an
    error.

- [ ] **#14 Reject an entire malformed plugin command** — high, 5.3 (`I4/U4/E3`)
  - Evidence: `zellij-utils/src/plugin_api/plugin_command.rs:709` and related conversions use
    `filter_map`, silently dropping invalid actions or pane IDs from multi-part commands.
  - Complete when repeated fields collect as `Result<Vec<_>>`, no partial destructive operation is
    emitted, and tests mix one invalid member with valid members.

- [ ] **#15 Isolate writable WASI preopened directories** — high, 4.0 (`I4/U3/E3`)
  - Evidence: `zellij-server/src/plugins/plugin_loader.rs:562` exposes shared host, data, cache, and
    temporary directories to every Wasm plugin instance.
  - Complete when writable storage is scoped per plugin/session, existing supported persistence
    continues to work, and plugins cannot read another plugin's temporary files.

- [ ] **#16 Mark recordings incomplete after persistence failure** — high, 4.0 (`I4/U3/E3`)
  - Evidence: `zellij-server/src/session_recorder.rs:266` logs failed store mutations, clears the
    affected batch, and can still finalize the recording as complete.
  - Complete when the first storage error is retained, further success is not claimed, and a
    failure-injection test observes an incomplete recording with an actionable reason.

- [ ] **#17 Make logger initialization fallible** — high, 4.0 (`I4/U3/E3`)
  - Evidence: `zellij-utils/src/logging.rs:26` unwraps directory, file, appender, configuration, and
    logger setup before normal diagnostic handling exists.
  - Complete when setup returns a contextual error, CLI and pty-host entry points fall back to
    stderr without panicking, and an unusable log directory is tested.

- [ ] **#18 Verify protobuf freshness by content** — high, 4.0 (`I4/U3/E3`)
  - Evidence: `xtask/src/build.rs:420` decides whether to regenerate committed bindings from file
    modification times, which are unreliable across checkout and rebase operations.
  - Complete when the handoff gate forces code generation and fails on a tracked generated diff;
    ordinary builds may retain the fast mtime shortcut.

- [ ] **#19 Terminate SSH option parsing before the host argument** — high, 4.0 (`I4/U1/E1`)
  - Evidence: `zellij-server/src/pty_host/remote/ssh.rs:518,639` passes a configured host directly
    after options, so a host beginning with `-` can be interpreted as another SSH option.
  - Complete when both bootstrap and forwarding commands terminate option parsing and tests cover
    a dash-prefixed host without spawning real SSH.

- [ ] **#23 Consolidate client teardown sequencing** — high, 3.0 (`I3/U3/E3`)

  - Complete when one helper owns the common lifecycle and focused tests cover exit, detach,

- [ ] **#24 Reject out-of-range protobuf identities** — medium, 3.0 (`I3/U1/E1`)

- [ ] **#25 Distinguish query errors from a missing pane or tab** — medium, 3.0 (`I3/U3/E3`)

- [ ] **#26 Remove avoidable per-event and per-frame copying** — medium, 3.0 (`I3/U2/E2`)

- [ ] **#27 Route pane access through one overlay-aware store API** — medium, 3.0 (`I3/U2/E2`)

- [ ] **#28 Report terminal restoration failures non-fatally** — medium, 2.0 (`I2/U2/E2`)
